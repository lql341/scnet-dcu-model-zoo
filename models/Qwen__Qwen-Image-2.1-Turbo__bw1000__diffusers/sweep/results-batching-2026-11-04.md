# Qwen-Image 合批优化：**不可行**（显存是硬上限）

目的：官方 60 prompt × 3 seed = 180 张，逐张约 19.8 s。想利用"同 prompt 的 3 个 seed 文本编码完全相同"
这一点，把 3 张合成一次 pipeline 调用，减少重复的文本编码与调度开销。

## 实测结论

| 配置 | 结果 |
| --- | --- |
| batch=1（官方评测实际用法） | ✅ 19.8 s/张，180 张 3558 s，显存够 |
| batch=2（同 prompt 两个 seed 合批） | ❌ `OutOfMemoryError`：已分配 46.56 GB，仅剩 3.84 GB，还需 6.75 GB |
| batch=3 | ❌ 同上（更早 OOM） |

**根因**：`use_kv_cache=True` + 2048×2048 latent 下，单张常驻显存已接近 64 GB 上限
（46.5 GB 常驻 + 每张新增 ~6.8 GB 峰值），**batch=1 本身就是显存上限**，没有合批余量。

## 判定

- 合批这条优化路径在 64 GB 单卡上**不可行**，不再尝试；除非改多卡（该 pipeline 不支持 TP/PP）
  或用 CPU offload（会更慢，违背目的）
- 保留 `sweep/batch3.py` 作为可复现的反证：`MAX_BATCH=2 PROBE_PROMPTS=8` 即可复现 OOM
- 顺带确认：官方 180 条的 19.8 s/张 已经接近这套硬件+框架的效率上限

## 附：这批实验的成本

3 次探针作业（含一次全量失败），约 1.5 卡时。结论本身比"再试 8 种参数"更有价值：
**Qwen-Image 的瓶颈是显存不是算力**，后续要提速只能换硬件或换框架。
