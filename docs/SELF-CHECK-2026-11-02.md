## 二、最重要的一条：T03/T04 **不需要 6 档基准**

官方主文档原文：

> 本项目只提供固定测试数据和使用说明。用户自行完成模型适配、部署和测试，返回真实输出与简短反馈；
> **不限定框架或调用方式，不要求提供服务接口，不进行统一评分和性能比较。**

这推翻了我们此前的假设。我们原来给 ASR 条目标 `bench = no-material`（理由是"语音类测法随材料下发"），
**现在材料到了，官方的答复是"不测性能"**。

因此需要给条目规范加一个新取值：

| `meta.bench` | 含义 |
| --- | --- |
| `yes` | 已做 6 档基准（T01/T02 文本类） |
| `no-material` | 测法/评测集未下发，暂时做不了 |
| **`not-required`** | **官方明确不要求性能比较**（T03/T04 全部） |

ASR 条目应从 `no-material` 改为 `not-required`，`bench_note` 改为引用官方原文。

## 三、ASR 条目逐项复核：6 项差距

官方条件（`formal/conditions/qwen3_asr.jsonl`，300 条）与我们的现状比对：

| # | 官方要求 | 我们现状 | 差距 |
| --- | --- | --- | --- |
| 1 | 300 条：AISHELL-1 test 100（zh）+ LibriSpeech test-clean 100 + test-other 100（en） | 1 条自造 TTS 音频 | ❌ **必须补正式评测** |
| 2 | `max_new_tokens = 1024` | smoke 用 `max_tokens = 256` | ❌ 参数不符 |
| 3 | `language = null`（自动识别，且**不得传语言标签**） | 未传 language | ✅ 一致；返回体里确有 `language Chinese<asr_text>` |
| 4 | **只传 `assets.audio` 与 `params`，不传参考 `text`** | 我们没传 | ✅ 一致 |
| 5 | 输出为 `<id>.txt`（UTF-8） | 无此产物 | ❌ 需补 |
| 6 | 提交 `反馈表.csv` + `环境说明`（含权重版本、框架版本、设备型号数量） | 无 | ❌ 需补 |

另外一条：官方明写「**不能直接把数据集里的参考答案当作测试结果**」——
我们之前的 `assets/asr_test.wav`（macOS TTS 合成、参考文本抄自模型卡示例）**不能替代官方数据**，
它只能作为链路 smoke。这点要在 README 里写清楚，避免混淆。

**一个巧合值得记录**：官方 ASR 清单第一条就是 `BAC009S0764W0121` /「甚至出现交易几乎停滞的情况」——
与我当初选做 smoke 的那句话完全相同（因为那句话出自官方模型卡示例）。所以并非我猜中了数据，纯属同源。

**关于两个 2048 / 1024 的口径冲突**（值得去群里确认）：
- 赛事详情 §三 T03 原文：「采用 **1024×1024** 的图片输出作为文生图的**性能测试**标准」
- 本材料 T03 原文：「**输出尺寸固定为 2048×2048**，输出图像」——这是**质量测试**的固定条件

两者一个说性能、一个说质量，很可能并不矛盾，但必须确认，否则产物尺寸填错就白跑。
