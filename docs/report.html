4. 五条硬约束（换框架、换参数都过不去）

#约束证据
1vLLM 在 DCU 上没有 paged-attention 内核，只有 Triton 兜底 五个旋钮全试过全部无效：chunked 切片 / AITER / backend 覆盖 / fp8 KV / TP=2 / v0 引擎。16K TPOT 119 ms（SGLang 24 ms）
2fp8 在线量化无内核--quantization fp8 → engine core 初始化即失败
314B 级视频模型单卡装不下Wan2.1 单卡 OOM（offload + t5_cpu 仍打满 63.98 GB）→ 必须 4 卡 FSDP
42048² 文生图没有合批余量Qwen-Image batch=2 即 OOM（已分配 46.56 GB / 剩 3.84 / 需 6.75）
5HY-World 重建需 ROCm 版 gsplatworldrecon/rasterization.py 硬 import gsplat；官方要 py3.11 + FA2/FA3

5. 技术路线（可复用的方法论）

5.1 三层环境隔离

镜像（不动）→ /opt/*-libs（--no-deps + cp310 轮子）→ PYTHONPATH 前置。 永不 pip install 到系统目录，永不升级镜像里的 torch。
为什么强调 cp310：按宿主机 py3.12 下载的轮子装进 py3.10 镜像，pip 会静默拒装，表现为 ModuleNotFoundError，曾把两个条目误判成 blocked。

5.2 参数只从条件清单读

官方 conditions/*.jsonl 是唯一权威。曾因写死 use_kv_cache 却不传 num_inference_steps，实际按 pipeline 默认 40 步跑（官方要 8 步），180 条产物差点全废。

5.3 验规格，不验「作业成功」

音频看 24 kHz/单声道、图像看 2048²、视频看 81 帧/16 fps，spec_violation_count 必须为 0。
OmniWeaving 首轮 60 条「全部成功」，实际是 848×480（官方要 832×480）—— 因为 --aspect_ratio 16:9 落到了最近的尺寸桶。这是靠逐条读 mp4 header 才发现的， 只看「文件存在且 >200 KB」会一路绿到底。 现在有 tools/check_products.py 守门。

5.4 续跑优先

单条 1–26 min 的任务一律「产物存在则跳过」。收益是实测的：账号被回收时 OmniWeaving 跑了 22 小时被砍，53/60 产物完好，只需补 3.5 小时。

5.5 阴性结论同样入库

不可行的路径要写清「试了什么、错在哪、什么条件才能过」，避免下个会话重复烧卡时。 §4 的五条硬约束和 §3 的「不必再做的清单」都是这么来的。

5.6 归档先于结论

镜像/轮子在用完之后立刻归档 + sha256 + 功能性还原验证（不是只算哈希：真的 load 起来跑一条）。 三个镜像现在是唯一能复现这套环境的资产。

7. 踩坑清单（32 条，按隐蔽度排序）

  • #1 `/dev/mkfd` 必须传（最难定位）
  • #2 CUDA Graph 的假陷阱
  • #3 `/etc/subuid` 为空导致 rootless podman 无法解包
  • #4 容器存储不能放 NFS
  • #5 私有 registry 的自签证书 + 只读 client key
  • #6 rootless podman 缺 runtime 目录
  • #7 不要用宿主 DTK 覆盖容器内 `/opt/dtk`
  • #8 `libmsgpackc.so.2` 藏在 lightop 里
  • #9 Notebook 镜像的 ENTRYPOINT 会吞掉命令
  • #10 `/tokenize` 在大词表模型上会 500
  • #11 `--context-length` 必须留余量（会产出假数据）
  • #12 sbatch 下 `$0` 不是脚本路径
  • #13 节点根盘水位极不稳定
  • #14 多卡容器：`HIP error: invalid device ordinal`
  • #15 SGLang 默认选到的 `aiter` attention backend 残缺
  • #16 容器保活后，容器状态不再能反映服务健康
  • #17 `Qwen3VLForEmbedding` 两个框架都不支持
  • #18 离线 wheel 是按 `cp312` 下的，容器却是 py3.10（最贵的一次误判）
  • #19 `torchaudio.save()` 同样要走 torchcodec
  • #20 官方条件清单里的 `params` 必须逐条读取，别信 pipeline 默认值
  • #21 vLLM 在 DCU 上的 16K decode 慢 5–7 倍，且**任何参数都改不动**
  • #22 量化在 DCU 上是「有路但没铺」：vLLM 在线 fp8 直接起不来
  • #23 视频 pipeline 的"分辨率桶"会静默改尺寸（832×480 → 848×480）
  • #24 临时账号不是存储：分区的 `AllowAccounts` 会被移除
  • #25 换账号重启时的三个坑（多账号共享节点）
  • #26 同一台机器上换账号：`WORK` 路径不改会写进别人家目录
  • #27 同一模型「SGLang 能跑、vLLM 不能」常常是版本问题
  • #28 `ModelRegistry.get_supported_archs()` 的 grep 别用下划线
  • #29 Harbor 搜索：搜不到 ≠ 没有，关键词要试多个
  • #30 申请 `--gres=dcu:4` 只分到 1 张卡：`-c` 太小，分配被静默缩水
  • #31 多卡起不来先看 `AllocTRES`，不要先怀疑容器
  • #32 多 rank 全量加载编码器 → 宿主 OOM kill（exitcode -9，无 traceback）

前三条最贵：① /dev/mkfd 必须传（否则 torch.cuda.is_available() 为 False 却 device_count() 为 1）； ② CUDA Graph 的假陷阱；③ /etc/subuid 为空导致 rootless podman 解包失败。
